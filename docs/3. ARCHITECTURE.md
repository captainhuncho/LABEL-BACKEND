# Architecture

Summary only. The source of truth is the linked doc; when they disagree, the code wins, then that doc, then this file.

Source: [AGENTS.md](../AGENTS.md) (Backend; Where things live) and [SECURITY.md](../SECURITY.md) (Where things run).

## Stack
React 18 + Vite, Tailwind plus inline styles, Recharts, PapaParse and xlsx for imports/exports, Supabase (Postgres, Auth, Edge Function `notify`), Resend for email, Vercel static hosting.

## Shape
One app, two addresses (team ops and Artists Access; `isArtistSite()` in `src/AuthGate.jsx`). Data goes through `window.storage` (`src/storage.js`): Supabase when configured, localStorage otherwise.

## Hosting
Live at https://ops.imssrecords.com (team) and https://artist.imssrecords.com (artists). Vercel project `label-backend`; every push to `main` deploys to production.

## Codebase map (graphify)
`graphify-out/graph.html` is an interactive map of the code, migrations and docs; `graphify-out/GRAPH_REPORT.md` is its summary. Rebuild with `/graphify . --update`. The report's suggested questions, checked against the code (2026-10-20):

- **Why is `RecordLabelDashboard()` the bridge between almost every area?** By design. It is the team app's root (`src/App.jsx`, lines 350–820): it loads every section from `window.storage`, owns every `updateX()` save function, works out permissions (`permissionsFor`, `pmScope`) and passes data and savers to each screen as props. No screen talks to storage directly. A change there reaches every screen, so test widely after editing it.
- **Are its 13 inferred links (`refresh()`, `updateRoster()`, …) right?** Yes. They are functions declared inside the component (e.g. `updateRoster`, line 592: set state, `persist('roster', …)`, then `logChange`) and handed to screens as props, which is why the parser could only infer them.
- **What connects `autoprefixer`, `postcss`, `tailwindcss`?** Build tooling only: `postcss.config.js` runs Tailwind and Autoprefixer over `src/index.css` (`@tailwind` directives). No runtime code imports them, so they have no links. The other weakly linked nodes are small local handlers (`openAdd()`, `remove()`, …) inside screens.
- **Should "App Shell & Libraries" be split?** No. Its low cohesion comes from shared libraries (`react`, `lucide-react`, `recharts`) that every file imports, which the clustering groups together. It is not a module in the code.
- **Why does `15. Debugging` link security docs to error reporting?** It is the troubleshooting guide: it points to `src/errorReport.js` and the `DATA_VERSION` reseed gate. A real link.
- **Should the Finance Engine be split?** No. `src/finance.js` (~360 lines, 32 exports) is one set of pure money functions, each used by different screens, so the graph sees few links between them. Keeping all money math in one file is a rule (AGENTS.md: single source of truth).
- **Should "Artists Access Data" be split?** Already done: `src/ArtistApp.jsx` loads `artist_portal()`, `src/sections/ArtistPortal.jsx` is the shell, and each tab is its own file in `src/sections/portal/`. The low score reflects shared helpers (`formatCurrency`, `logActivity`) across tabs.
