# Debugging

Summary only. The source of truth is the linked doc; when they disagree, the code wins, then that doc, then this file.

## Where to look
Browser console; `src/errorReport.js`; Supabase logs (Auth, Database, Edge Functions); Vercel deployment logs.

## Common problems
A blocked sign-in: the email isn't on Team or a Roster entry (Team shows blocked sign-ins for 30 days). Data looks reset: check `DATA_VERSION`. PM sees an empty roster: no `productManager` set on the artists.

## Incident runbook
1. **Is it down?** Open https://ops.imssrecords.com and https://artist.imssrecords.com. The `uptime` workflow (once switched on) emails the repo owner when either fails.
2. **Bad deploy:** Vercel → project `label-backend` → Deployments → the last good one → Promote to Production (Max only). Then revert the commit on `main`.
3. **Errors in the app:** Backup & Restore shows client errors (`src/errorReport.js`, `private.client_errors`, kept 30 days). Server side: Supabase logs (Auth, Postgres, Edge Functions `notify`).
4. **Emails not going out:** Email notifications page lists batches that gave up; cron `email-retry` retries every 10 minutes, 5 attempts.
5. **Data wrong or lost:** Admin restores a daily copy (`restore_backup`; the current state is archived first as `pre-restore-<time>`). Off-site copies: SECURITY.md → Backups. Ask Max before any restore.
6. **Supabase paused or down:** the free plan pauses after a week without use; restore it from the Supabase dashboard (Max only).
