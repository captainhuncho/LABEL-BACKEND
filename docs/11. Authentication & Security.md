# Authentication & Security

Summary only. The source of truth is the linked doc; when they disagree, the code wins, then that doc, then this file.

Source: [SECURITY.md](../SECURITY.md).

## Sign-in
No passwords: Google or an emailed one-time code (Supabase Auth via Resend). Invite only, enforced in the database (`private.is_invited`, Before User Created hook). Team members need a passkey or authenticator app as a second step.

## Access
RLS on `app_data`; artists only see their own rows through `artist_portal()`. Each portal section, and each Label Rep release (`rep_portal()`), is an allowlist of the fields its screens show (see SECURITY.md, `20261027_portal_field_allow_lists.sql`).

## Risks
The repo contains real roster and revenue data: keep it private. Known limits in SECURITY.md.

## 2026-10-20 hardening
Artists Access payload minimized; Product Manager write scope and Admin-only ledger/revenue approval enforced in the database; SECURITY DEFINER audit (all pin search_path and check the caller; private helper grants revoked; `app_data_check_write` only inside the save trigger); production fails closed without Supabase settings. Details and remaining gaps: SECURITY.md.
